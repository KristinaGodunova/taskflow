  
# TaskFlow (Jira-lite)

Веб-приложение для управления задачами на канбан-досках с поддержкой совместной работы, Drag-and-Drop и обновлениями в реальном времени.

## 🗄 Развертывание базы данных (Supabase Migrations)

Проект полностью самодостаточен и воспроизводим с нуля. В директории `supabase/migrations/` находятся все миграции:

1. **`001_schema.sql`** — базовая схема таблиц (`profiles`, `boards`, `board_members`, `columns`, `tasks`, `comments`), поле дедлайна строго по модели `due_date date`, триггер создания профиля при регистрации и публикация `supabase_realtime`.
2. **`002_rls.sql`** — включение Row Level Security (RLS) для всех таблиц, строгая ролевая модель (изменение структуры колонок только `owner`, задачи — `owner` + `member`) и функция проверки доступа `is_board_member` без рекурсии.
3. **`003_board_trigger.sql`** — автоматический триггер: при создании доски владелец добавляется в `board_members` со статусом `owner`, а также генерируются 3 колонки по умолчанию («To Do», «In Progress», «Done»).
4. **`004_invite_rpc.sql`** — хранимые процедуры PostgreSQL: `invite_user_by_email` (приглашение на доску по email) и `reorder_tasks` (пакетное сохранение нормализованных позиций задач в одной транзакции).
5. **`005_storage.sql`** — создание публичного бакета `avatars` и политики доступа Supabase Storage для загрузки аватаров пользователей.
6. **`006_security.sql`** — ужесточение безопасности: функция `reorder_tasks` переведена на `security invoker` (изменение позиций проходит через RLS-политики таблицы `tasks`), в `invite_user_by_email` исправлена проверка роли для пользователей, не состоящих в доске, обе RPC-функции доступны только роли `authenticated`; политики Supabase Storage ограничивают загрузку и обновление аватаров папкой владельца (`{user_id}/avatar.*`); триггер создания профиля защищён от повторной вставки (`on conflict do nothing`).

### Как применить миграции:
- **Способ 1 (через веб-интерфейс):** В дашборде Supabase откройте **SQL Editor** -> поочередно скопируйте и выполните содержимое файлов с `001` по `006`.
- **Способ 2 (через Supabase CLI):**
  ```bash
  npx supabase link --project-ref <your-project-ref>
  npx supabase db push
  ```


## 🚀 Локальный запуск проекта

### 1. Клонирование репозитория
```bash
git clone https://github.com/kristinagodunova/taskflow.git
cd taskflow
```

### 2. Установка зависимостей
```bash
npm install
```

### 3. Настройка переменных окружения
```bash
cp .env.example .env
```
```env
VITE_SUPABASE_URL=https://your-project-id.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-public-key
```

### 4. Запуск в режиме разработки
```bash
npm run dev
```
Приложение откроется по адресу http://localhost:5173

### 5. Сборка для продакшена
```bash
npm run build
```

### 6. Запуск тестов
```bash
npm test
```

## 🏛 Архитектурные особенности решения

  - Декомпозиция страницы доски: логика BoardDetailPage разделена на
    сфокусированные хуки (useBoard, useBoardMutations, useTaskDnD) и
    изолированные UI-компоненты (BoardToolbar, BoardCanvas), что делает код
    читаемым и поддерживаемым.
  - Строгий TypeScript: проект компилируется в режиме "strict": true, клиент
    Supabase типизирован схемой Database, исключены неявные приведения типов
    any.
  - Оптимистичный UI и консистентность: Drag-and-Drop обновляет кэш React Query
    мгновенно, а в базе данных порядок фиксируется пачкой через PostgreSQL RPC,
    исключая коллизии одинаковых индексов.
